## 4. 本地开发

### 4.1 后端

```bash
cd warehub-api
mvn spring-boot:run -Dspring-boot.run.profiles=h2   # 演示模式，H2 内存库
# 或使用生产配置（需本机 MySQL 与 JWT_SECRET）
export JWT_SECRET=your-secret-at-least-32-bytes
mvn spring-boot:run
```

### 4.2 前端（开发热更新）

```bash
# PC 后台
cd warehub-ui-admin && npm install && npm run dev   # http://localhost:5173

# 移动 H5
cd warehub-ui-mobile && npm install && npm run dev  # http://localhost:5174
```

开发模式下前端通过 Vite 代理 `/api` 到后端 `http://localhost:8080`，需先启动后端。

## 5. 构建与打包

后端打包会自动将两个前端 `dist/` 合并进 JAR 的 `static/` 目录：

```bash
# 1) 构建前端
cd warehub-ui-admin && npm install && npm run build
cd ../warehub-ui-mobile && npm install && npm run build

# 2) 构建后端单 JAR（含三端静态资源）
cd ../warehub-api && mvn clean package -DskipTests
# 产物：warehub-api/target/warehub-api-1.0.0.jar
```

> 若仅改后端，前端 `dist/` 已存在时可直接 `mvn clean package`。

## 6. 部署

### 6.1 演示模式（零依赖，开箱即用）

```bash
java -jar warehub-api-1.0.0.jar --spring.profiles.active=h2
```

首次启动自动用 `schema-h2.sql` 建表并播种菜单/角色/管理员/演示数据。

访问入口：

| 端 | 地址 |
| --- | --- |
| PC 管理后台 | http://localhost:8080/ |
| 移动 H5 | http://localhost:8080/m |
| H2 控制台 | http://localhost:8080/h2-console（`sa` 空密码） |
| API 文档 | http://localhost:8080/doc.html |

默认账号：`admin` / `admin123`

### 6.2 生产模式（MySQL）

```bash
# 1) 准备数据库
mysql -u root -p -e "CREATE DATABASE warehub DEFAULT CHARACTER SET utf8mb4;"
mysql -u root -p warehub < warehub-api/src/main/resources/schema.sql

# 2) 启动（环境变量注入敏感信息）
export DB_HOST=localhost
export DB_USERNAME=root
export DB_PASSWORD=yourpassword
export JWT_SECRET=your-secret-at-least-32-bytes   # 必填，缺失将启动失败
java -jar warehub-api-1.0.0.jar --spring.profiles.active=prod
```

### 6.3 Docker Compose

```bash
cd docker
cp ../warehub-api/target/warehub-api-1.0.0.jar warehub.jar
docker compose up -d
```

`docker-compose.yml` 编排 MySQL 8 与应用容器，应用自动连接 `mysql` 主机。生产环境请修改 `MYSQL_ROOT_PASSWORD` 与 `JWT_SECRET`。

## 7. API 约定

- 统一前缀：`/api`
- 认证方式：`Authorization: Bearer <accessToken>`
- 统一响应：

```json
{ "code": 200, "message": "success", "data": {} }
```

- 分页请求：`pageNum`（默认 1）、`pageSize`（默认 10）；响应 `PageResult{ total, records }`（**字段名为 `records`，非 `list`**，前端取数据请用 `res.records`）
- 错误码：`200` 成功；`400` 参数错误；`401` 未认证；`403` 无权限；`500` 服务异常
- 在线文档：`/doc.html`（Swagger UI），`/v3/api-docs`（OpenAPI JSON）

## 11. 常见问题

**Q：生产启动报 "JWT_SECRET 未配置"？**
A：必须设置环境变量 `JWT_SECRET`（≥32 字节），这是安全加固要求。

**Q：前端页面 404 / 白屏？**
A：`/` 会重定向到 `/admin/index.html`，请确认 JAR 内 `static/admin`、`static/mobile` 存在（构建时已合并前端 dist）。

**Q：H2 演示模式如何重置数据？**
A：内存库随进程销毁，重启即重置。若需保留，可改用 MySQL 模式。

**Q：审核开关如何调整？**
A：修改 `warehub.audit.*` 配置项后重启。调拨默认免审核，提交后直接进入待执行。

**Q：如何新增微信小程序？**
A：后端已预留 `/mp/**` 静态资源路由（当前兜底复用移动 H5），小程序构建产物放入 `static/mp/` 并将 `PageController` 的 `/mp` 指向 `/mp/index.html` 即可。

## 12. 上线审计与修复记录（v1.0.0 发布前）

> 说明：以下为发布 pro 环境前的全链路实操审计发现与修复，均已在代码中落地并通过回归验证。

### 12.1 审计方法

H2 演示模式启动后端 → 实操跑通全链路（入库/出库/调拨/盘点/审核/库存/预警/流水）+ 边界场景（幂等、库存不足拦截、驳回、越权、参数校验、非管理员权限）→ 前端 PC/移动端构建 → 打完整 Fat-JAR 模拟生产启动，验证三端页面与接口。

### 12.2 已修复问题清单

| 级别 | 问题 | 现象 | 修复 |
| --- | --- | --- | --- |
| P0 | 刷新令牌接口前后端传参不匹配 | 前端（PC+移动端）用 JSON body 调 `/auth/refresh`，后端仅接受 query 参数，导致 access 过期（2h）后被强制登出 | 接口兼容 query 与 JSON body 两种传参，并回传新 refreshToken（`AuthController`） |
| P0 | 入库单无法创建 | `InboundCreateDTO.actualQuantity` 设 `@NotNull`，但前端开单只传计划数量，创建报 400 | 移除 `@NotNull`，业务 `createInbound` 已有空则取计划数量的兜底（`InboundCreateDTO`） |
| P0 | 出库单无法创建 | 同上 `OutboundCreateDTO.actualQuantity` | 同上移除校验（`OutboundCreateDTO`） |
| P0 | 非管理员登录后无法进首页 | 仪表盘路由要求 `perm:'dashboard'`，后端无此权限码、数据库未播种，守卫 `next(false)` 卡死 | 移除路由 `perm`（与侧边栏 MENU 无 perm 一致，所有登录用户可看首页）（`warehub-ui-admin/src/router/index.js`） |
| P1 | 权限码不一致 | 调拨/盘点提交、执行后端校验 `:add`，数据库播种了 `:submit`/`:execute`，仅勾选细粒度权限的角色功能 403 | 权限切面改为「或」语义；接口补多权限码 `transfer:add/submit/execute`、`stocktake:add/submit/execute`（`PermissionAspect`、`InventoryController`） |
| P1 | 生产 CORS 白名单硬编码 localhost | 生产域名未配置时跨域全失败 | CORS 改为环境变量 `WAREHUB_CORS_ORIGINS`（见 §6.4） |
| P1 | 生产 SQL 全量打印 + DEBUG 日志 | 性能损耗与敏感信息泄露风险 | 关闭 `mybatis-plus` SQL 打印，根/业务日志级别改 INFO（`application.yml`） |
| P1 | 启动横幅端口硬编码 8080 | 非默认端口部署时地址误导 | 横幅动态读取 `server.port` 与 `server.servlet.context-path`（`WareHubApplication`） |

### 12.4 上线前必做（pro 部署清单）

1. **设置 `JWT_SECRET`**（≥32 字节，缺失启动失败属预期安全保护）
2. **设置 `DB_HOST/DB_PORT/DB_USERNAME/DB_PASSWORD`** 指向生产 MySQL，并先执行 `schema.sql` 建表
3. **设置 `WAREHUB_CORS_ORIGINS`** 为实际前端域名（前后端同域可保持默认）
4. **首次启动后立刻修改 `admin` 密码**（默认 `admin123` 为弱密码，已在公开文档中）
5. 构建顺序：先 `npm run build`（两个前端）→ 再 `mvn clean package`（pom 已配置拷贝 `dist` 到 `static`）
6. 预置角色已含 `transfer:submit`/`stocktake:submit` 等细粒度权限码，可在角色管理页按需授权
