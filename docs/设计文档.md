# 仓枢 WareHub 设计文档

> 版本：1.0.0 ｜ 更新日期：2026-08-30 ｜ 适用代码版本：main 分支

## 1. 项目概述

仓枢 WareHub 是一款面向中小型企业的**轻量化仓库管理系统（WMS）**。系统采用**单体架构**，一个 Spring Boot 应用包覆盖全部后端业务，同时托管 PC 管理后台、移动 H5、微信小程序三端静态资源，实现"一个包部署、零中间件依赖"。

### 1.1 产品定位

| 维度 | 说明 |
| --- | --- |
| 目标用户 | 中小型制造/贸易企业，年营收 5 千万以下的仓管场景 |
| 业务范围 | 物料档案、库存收发存、仓库/库位、审核流、人员权限、仪表盘 |
| 终端形态 | PC 管理后台（Element Plus）、移动 H5（Vant，扫码作业/审批）、微信小程序（预留） |
| 部署形态 | 单 Fat-JAR 或 Docker Compose，可演示模式（H2）零依赖启动 |

### 1.2 设计原则

1. **单体优先**：全部业务收敛于一个 Spring Boot 应用，无微服务拆分，降低部署与运维成本。
2. **依赖最小**：仅强依赖 MySQL（生产）；缓存使用本地 Caffeine，不引入 Redis/MQ/ES。
3. **配置驱动**：审核开关、单号前缀、物料编码规则等全部走 `application.yml`，不建配置表、不引工作流引擎。
4. **开箱即用**：内置 `h2` profile，首次启动自动建表并播种菜单、角色、管理员与演示数据。
5. **并发可控**：库存表以 `version` 字段做乐观锁，避免分布式锁的复杂度。

## 3. 模块设计

### 3.1 认证与权限（RBAC）

- **认证**：`POST /api/auth/login` 校验 BCrypt 密码后签发 JWT（access 2h / refresh 7d），无状态会话。
- **鉴权**：Spring Security 过滤链 + `@HasPerm("xxx:yyy")` 注解 + `PermissionAspect` 切面校验权限码；路由级权限由前端 `meta.perm` 配合 `beforeEach` 守卫二次拦截。
- **数据模型**：`wms_user` —(N:N)— `wms_role` —(N:N)— `wms_menu`，菜单表同时承载"菜单"与"按钮权限码"两类资源（`menu_type` 1=菜单 2=按钮）。
- **预置角色**：系统管理员（全部权限）、仓库主管（作业+审核）、库管员（作业录入）、查询员（只读）。

### 3.2 物料模块

- 物料分类：两级树（`parent_id`），编码唯一。
- 物料档案：编码（按类型前缀自动生成）、名称、规格、单位、类型（RAW/SEM/FIN/AUX）、安全库存、最大库存、条码。
- 能力：分类树 CRUD、物料 CRUD、Excel 导入导出（Apache POI）。

### 3.3 库存模块

核心单据四类，全部遵循同一状态机（见 §5）：

| 单据 | 业务含义 | 明细存储 | 库存影响 |
| --- | --- | --- | --- |
| 入库单 `wms_inbound_order` | 采购/生产/退货入库 | 独立明细表 | 增加库存 |
| 出库单 `wms_outbound_order` | 销售/领用出库 | 独立明细表 | 减少库存（锁定→扣减） |
| 调拨单 `wms_transfer_order` | 跨仓/跨库位移库 | 明细 JSON（`items` TEXT） | 调出-、调入+ |
| 盘点单 `wms_stocktake_order` | 账面 vs 实盘 | 明细 JSON（`items` TEXT） | 差异调整 |

- **库存模型**：`wms_stock` 以「仓库 + 库位 + 物料 + 批次」为唯一维度，含 `quantity` 可用量与 `locked_quantity` 锁定量，`version` 乐观锁。
- **出库流程**：提交/执行时先校验并锁定库存 → 实际出库扣减并写流水。
- **库存流水**：`wms_stock_log` 记录每次变动（`change_quantity` 正入负出、变动前后快照、操作人），支撑追溯与前端流水页。
- **库存预警**：`quantity < safety_stock` 或 `> max_stock` 判定，支撑预警列表与仪表盘。

### 3.4 基础资料

- 仓库 `wms_warehouse`：编码唯一、负责人、地址。
- 库位 `wms_location`：隶属仓库，两级简化（仓库→库区→库位，`zone_code` 标识库区）。
- 部门 `wms_department`：树形，用户挂靠部门。

### 3.5 审核模块

- 业务开关：`warehub.audit.{inbound,outbound,transfer,stocktake}` 四个开关控制各单据是否走审核。
- 审核动作：`/api/audit/**` 通过/驳回，写 `wms_audit_record` 并回写单据 `audit_user/audit_time/audit_remark`。
- 审核通知：`AuditNotificationService` 在单据提交后通知具有审核权限的用户。
- 状态流转：单据待审核 → 审核通过 → 待执行 → 完成；驳回 → `REJECTED` 可重提。

### 3.6 系统管理

- 用户/角色/菜单/部门管理，角色赋权（`role:perm`）。
- 操作日志：`@Log` 注解 + `OperationLogAspect` AOP，记录操作人、模块、参数、IP、耗时到 `wms_operation_log`。

### 3.7 仪表盘

`/api/dashboard/overview` 聚合：库存总量、物料数、待审核单、库存预警等统计，供 PC 首页与移动端统计页使用。

## 4. 数据库设计

共 20 张业务表，统一前缀 `wms_`，全部含逻辑删除标记（`deleted`）或按表特性取舍：

```
wms_material_category ─┬── wms_material ──┬── wms_stock ──┬── wms_stock_log
wms_warehouse ─────────┼──────────────────┴───────────────┤
wms_location ──────────┘      (warehouse+location+material+batch 唯一)
wms_inbound_order ── wms_inbound_item
wms_outbound_order ── wms_outbound_item
wms_transfer_order   (明细 JSON)
wms_stocktake_order  (明细 JSON)
wms_department ── wms_user ── wms_user_role ── wms_role ── wms_role_menu ── wms_menu
wms_audit_record（业务单号关联）
wms_operation_log
```

### 4.1 关键表说明

| 表 | 核心字段 | 索引/约束 |
| --- | --- | --- |
| `wms_stock` | warehouse_id, location_id, material_id, batch_no, quantity, locked_quantity, version | 四元组唯一键；version 乐观锁 |
| `wms_stock_log` | change_type(IN/OUT/TRANSFER), business_type, business_order_no, change_quantity, quantity_before/after, operator | material_id、order_no 索引 |
| `wms_inbound_order` / `wms_outbound_order` | order_no, status, total_quantity, audit_user/time/remark | order_no 唯一 |
| `wms_transfer_order` / `wms_stocktake_order` | order_no, status, items(JSON), audit_* | order_no 唯一 |
| `wms_menu` | perm_code, menu_type(1菜单/2按钮), path | — |
| `wms_audit_record` | business_type, business_order_no, audit_result(1过/2驳) | order_no 索引 |

> 明细表（`wms_inbound_item`/`wms_outbound_item`）以 `order_id` 关联主表；调拨/盘点明细因结构简单采用 JSON 存储，减少表数量。

## 5. 单据状态机

四类单据统一状态机（调拨/盘点为 `PENDING` 单态，入库/出库区分 `PENDING_IN/PENDING_OUT`）：

```
            提交(提交按钮)        审核通过             执行(入库/出库/确认)
DRAFT ──────────────────► PENDING_AUDIT ────► PENDING_IN/OUT ──► COMPLETED
   │                        │  ▲                  │
   │                        │  └── 驳回 ──────────┤
   └────────── 驳回后修改重提 ┘    REJECTED ◄───────┘
```

- **DRAFT**：草稿，可编辑、可删除。
- **PENDING_AUDIT**：已提交待审核（若审核开关关闭则直接进入 PENDING_*）。
- **PENDING_IN / PENDING_OUT / PENDING**：审核已过，等待实际作业执行。
- **COMPLETED**：执行完成，库存与流水已更新（幂等，重复执行不会重复入账）。
- **REJECTED**：审核驳回，可修改后重新提交。

## 6. 关键设计决策

### 6.1 并发控制：乐观锁

库存增减通过 `UPDATE wms_stock SET quantity = quantity + ?, version = version + 1 WHERE id = ? AND version = ?` 实现，更新行数 = 0 时抛出冲突异常。无需引入 Redis 分布式锁。

### 6.2 缓存：Caffeine 本地缓存

`CacheConfig` 注册 `CaffeineCacheManager`，默认 TTL（如 5 分钟）。用于菜单树、字典类只读数据的本地加速，零外部组件。

### 6.3 安全设计

| 措施 | 实现 |
| --- | --- |
| 无状态 JWT | `JwtAuthenticationFilter` 解析 Bearer Token 并注入 `UserContext` |
| 权限码校验 | `@HasPerm` + `PermissionAspect`，`LoginUser` 缓存用户权限集 |
| 密码存储 | BCrypt 加盐哈希 |
| 防重提交 | `@RepeatSubmit` + 请求体缓存包装 + 拦截器（同 key 时间窗内拦截） |
| 生产密钥强制 | `warehub.jwt.secret` 读环境变量 `JWT_SECRET`，缺失则启动失败 |
| CORS 白名单 | `warehub.cors.allowed-origins` 配置，无通配 |
| 逻辑删除 | 全局 `logic-delete-field: deleted` |

### 6.4 单号生成

`OrderNoGenerator` 按 `warehub.code-rule.*-prefix`（IN/OUT/TR/PD）+ 日期 + 自增序列生成单据号，保证唯一。

## 7. 前端设计

### 7.1 PC 管理后台（warehub-ui-admin）

- 技术栈：Vue 3 + Element Plus + Pinia + Vue Router + Axios + Vite。
- 页面：登录、仪表盘、物料（分类/列表）、库存（入库/出库/调拨/盘点/库存查询/库存预警/库存流水/仓库/库位）、审核（待办/记录）、系统（用户/角色/菜单/部门）、403/404。
- 权限：路由 `meta.perm` + 全局 `beforeEach` 守卫；菜单由后端下发动态渲染。

### 7.2 移动 H5（warehub-ui-mobile）

- 技术栈：Vue 3 + Vant 4 + Pinia + Vue Router + Axios + Vite。
- 页面：登录、首页、工作台、入库、出库、调拨、盘点、库存查询、统计、审核、我的。
- 能力：扫码录入（`ScanField`，条码/二维码）、物料选择器、移动端审批。

### 7.3 微信小程序（warehub-ui-mobile/mp 预留）

- 后端已预留 `/mp/**` 静态资源路由与放行规则，小程序包可挂载同一后端 API。

## 8. 接口约定

- 统一前缀：`/api`。
- 认证：`Authorization: Bearer <JWT>`。
- 响应：`{ code, message, data }`（`R<T>` 封装，`code=200` 成功）。
- 分页：`pageNum/pageSize` 请求，`PageResult<T>{ total, list }` 响应。
- 在线文档：`/doc.html`（SpringDoc / Swagger UI）。

## 9. 部署形态

1. **演示模式**：`--spring.profiles.active=h2`，H2 内存库 + 自动播种，零外部依赖。
2. **生产模式**：`--spring.profiles.active=prod`，MySQL 8，环境变量注入 `DB_*` 与 `JWT_SECRET`。
3. **Docker**：`docker-compose.yml` 编排 MySQL + 应用容器，应用镜像内嵌单 JAR。

详见《技术文档.md》部署章节。
