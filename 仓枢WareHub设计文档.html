1. 项目概述

1.1 项目背景

中小型企业在仓储管理中普遍面临「Excel 管不动、大系统用不起」的尴尬：传统 WMS 部署重、依赖多、成本高、运维难，而纯手工台账又导致库存不准、追溯困难、审批混乱。

仓枢 WareHub 正是为这一痛点而生 —— 一套面向中小型企业的轻量化仓库管理系统，开箱即用、低资源占用、一键部署，覆盖物料、库存、人员、审核四大核心业务。

1.2 产品定位

维度定位
目标客户年营收千万级–亿级中小企业，仓储人员 10–50 人
核心价值轻量、易用、够用、低成本
部署形态单体单包部署，5 分钟启动；两端（PC 后台 / 移动 H5）共用一套后端

2. 轻量化设计理念

本章节是仓枢 WareHub 区别于传统重型 WMS 的核心设计准则。

2.1 轻量化原则

原则说明对比传统 WMS
单体优先一个 Spring Boot 应用包含全部功能，不做微服务拆分传统：Spring Cloud 多服务
依赖最小仅依赖 MySQL（必需）+ 可选 Redis，无 MQ/ES传统：MQ + ES + 注册中心全套
本地缓存优先默认 Caffeine 本地缓存，零额外组件传统：强制 Redis 集群
配置即代码审核规则用配置文件 + 枚举常量，减少配置表传统：大量配置表 + 动态引擎
内置演示库H2 内存数据库模式，下载即用、零安装传统：必须先装数据库
一键部署单个 Fat-JAR 同时托管 API 与两端前端静态资源，java -jar 即启动传统：前后端分离 + 多容器编排

2.2 轻量化取舍

✓ 保留（够用就好）

  • 四大核心业务模块完整功能
  • RBAC 权限模型（用户-角色-菜单）
  • 单级审核流程
  • 库存并发控制（DB 乐观锁 @Version）
  • 操作日志审计（@Log AOP）
  • 防重复提交（@RepeatSubmit + Caffeine）
  • 登录限流（5分钟5次失败锁定）

✗ 砍掉（避免过度设计）

  • 微服务、注册中心、网关
  • 消息队列（RabbitMQ/Kafka）
  • 读写分离、分库分表
  • ELK 日志栈、SkyWalking
  • 多级审核引擎、工作流引擎
  • 库区三级结构（简化为两级）

2.3 资源占用对比

指标仓枢 WareHub传统 WMS
部署组件数1–2（应用 + MySQL）5–8（多组件集群）
最低内存2GB8GB+
启动时间< 15 秒数分钟
运维复杂度低（单进程）高（多组件协同）
月度成本单服务器即可多服务器集群

3.4 前端多端设计

仓枢 WareHub 采用「后端单体、前端多端」模式：一套 Spring Boot 单体服务提供统一的 REST API，前端按使用场景拆为两端，互不耦合、独立打包、共用同一套后端与鉴权。

端技术使用人群核心场景
PC 管理后台
(admin)		Vue 3.4 + Element Plus 2.7 + Vite 5 + Pinia + Axios管理员、仓管主管物料维护、库存台账、单据审核、人员/权限、报表统计；桌面大屏操作
移动 H5
(mobile)		Vue 3.4 + Vant 4.8 + Vite 5 + Pinia + Axios仓管员、现场员工手机浏览器扫码出入库、盘点、调拨、待办审批；免安装、即开即用

3.4.1 多端路由与资源分发

单体应用内置 Tomcat 同时承载 API 与静态资源。由 PageController 负责 SPA 路由转发与深链回退，使用 redirect 而非 forward（前端 index.html 内资源为相对路径 ./assets/*，重定向后浏览器地址变为 /admin/index.html，资源才能正确解析为 /admin/assets/*）：

# 同一域名，不同路径进入不同端
/            →  PC 管理后台 (admin)      — redirect → /admin/index.html
/m           →  移动 H5 (mobile)         — redirect → /mobile/index.html
/mp          →  小程序 H5 兜底            — redirect → /mobile/index.html（复用移动端）
/m/{path}    →  移动 H5 SPA 深链回退       — redirect → /mobile/index.html
/api/**      →  后端 REST API（两端共用）

4. 功能模块设计

4.1 物料管理模块

编号功能说明
M-01物料分类树形分类维护（多级），hover 节点显示增/改/删
M-02物料编码按规则自动生成（分类码+类型码+流水号），支持手工录入
M-03物料维护基本信息、规格、单位、条码、安全库存的增删改查
M-04物料批次批次号记录，支持追溯
M-05物料查询多条件查询、条码查询、库存概览
M-06导入导出Excel 批量导入导出（Apache POI）
编码规则：「分类码 + 类型码 + 流水号」，示例 RM-RAW-000001。物料类型含 RAW（原材料）/ SEM（半成品）/ FIN（成品）/ AUX（辅料）/ PACK（包装材料）。物料含 barCode 字段支持扫码识别。

4.2 库存管理模块

编号功能说明
I-01仓库/库位仓库→库位 两级结构（轻量化，省去库区层；库位保留 zoneCode 字段）
I-02入库管理采购(PURCHASE)/生产(PRODUCTION)/退货(RETURN)入库
I-03出库管理领料(PICKUP)/销售(SALE)/调拨(TRANSFER)出库
I-04调拨管理库位间、仓库间调拨（明细 JSON 存储）
I-05盘点管理盘点计划(CYCLE/RANDOM/FULL)、执行、差异处理（明细 JSON 存储）
I-06库存查询实时库存、台账、流水追溯（含物料/仓库/库位名称）
I-07库存预警低于安全库存 / 超最大库存预警
单据状态机：草稿(DRAFT) → 待审核(PENDING_AUDIT) → 审核通过 → 待执行(PENDING/PENDING_IN/PENDING_OUT) → 已完成(COMPLETED) / 审核驳回退回(REJECTED)。调拨单/盘点单审核通过后状态为 PENDING；入库单为 PENDING_IN；出库单为 PENDING_OUT。

4.3 人员管理模块

RBAC 模型：用户(User) ─N:N─ 角色(Role) ─N:N─ 菜单权限(Menu)

权限 = 菜单权限（可见性）+ 按钮权限（操作权）。轻量化版省略数据权限范围配置。

预置角色roleCode职责

库管员keeper入库、出库、调拨、盘点录入（不含审核通过/驳回）

5. 数据库设计

设计原则：单库单实例，不分库分表；逻辑删除；公共审计字段统一（BaseEntity）；共 20 张表覆盖四大模块 + 公共功能。调拨单/盘点单明细以 JSON 字段轻量存储，减少表数量。

5.1 BaseEntity 公共字段

继承 BaseEntity 的实体自动获得：create_time（FieldFill.INSERT）、update_time（FieldFill.INSERT_UPDATE）、create_by（FieldFill.INSERT）、deleted（逻辑删除，0/1）。

5.3 核心 DDL

库存表（核心）

CREATE TABLE `wms_stock` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `warehouse_id` BIGINT NOT NULL,
  `location_id` BIGINT NOT NULL,
  `material_id` BIGINT NOT NULL,
  `batch_no` VARCHAR(64) DEFAULT '-',
  `quantity` DECIMAL(18,4) NOT NULL DEFAULT 0 COMMENT '库存数量',
  `locked_quantity` DECIMAL(18,4) DEFAULT 0 COMMENT '锁定数量',
  `version` INT DEFAULT 0 COMMENT '乐观锁版本号（@Version）',
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_stock` (`warehouse_id`,`location_id`,`material_id`,`batch_no`),
  KEY `idx_material` (`material_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='库存';

7. 关键业务流程

7.1 入库流程

① 创建入库单(草稿) → ② 填明细 → ③ 提交(待审核)
   → ④ 审核：通过→待入库(PENDING_IN) / 驳回→退回(REJECTED)
   → ⑤ 执行入库：校验库存 → 更新库存 + 写流水 → 已完成(COMPLETED)

库存写入核心逻辑（乐观锁轻量并发控制）

@Transactional(rollbackFor = Exception.class)
public void executeInbound(Long orderId) {
    InboundOrder order = getById(orderId);
    if (!"PENDING_IN".equals(order.getStatus())) {
        throw new BizException("单据状态不允许入库");
    }
    for (InboundItem item : itemMapper.listByOrderId(orderId)) {
        Stock stock = stockMapper.getOrCreate(order.getWarehouseId(),
                item.getLocationId(), item.getMaterialId(), item.getBatchNo());
        BigDecimal before = stock.getQuantity();
        stock.setQuantity(before.add(item.getActualQuantity()));
        // 乐观锁更新（MyBatis-Plus @Version，中小企业并发不高，DB 乐观锁足够）
        int rows = stockMapper.updateByIdWithVersion(stock);
        if (rows == 0) throw new BizException("库存已被修改，请重试");
        stockLogService.record(order, item, before, stock.getQuantity());
    }
    order.setStatus("COMPLETED");
    updateById(order);
}
轻量化取舍：中小企业并发量低，采用 DB 乐观锁（@Version 字段）即可，无需 Redis 分布式锁。高并发场景可平滑升级为 Redis 锁。

7.2 出库 / 调拨 / 盘点 / 审核流程

出库：创建 → 提交审核 → 审核通过(PENDING_OUT) → 执行出库（FIFO 按批次先进先出扣减）→ 已出库(COMPLETED)。

调拨：创建调拨单 → 填明细(JSON) → 提交（调拨默认免审核，直接 PENDING）→ 执行调拨（扣减源库位 + 增加目标库位 + 写流水）→ 已完成。

盘点：创建盘点单 → 生成账面数量 → 审核 → 录入实盘 → 计算差异 → 差异调整 → 审核确认。

审核：单据提交 → 读配置(warehub.audit.* 是否需审核) → 否则直接流转 / 是则通知审核角色 → 通过流转 / 驳回退回。

java -jar warehub-api-1.0.0.jar --spring.profiles.active=prod

java -jar warehub-api-1.0.0.jar --spring.profiles.active=h2 --server.port=8080
